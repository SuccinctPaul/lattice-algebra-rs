# L1 · NTT Engine

The NTT is the performance heart of every NTT-friendly parameter set: ML-KEM/ML-DSA matrix–vector products, LaBRADOR batched openings and GreyHound sumchecks all ride on it.

## Current state

`src/ntt/ntt_core.rs` (the single path — the legacy runtime version was deleted in M0):

- `NttOperator<R, N>` / `NttOperatorOptimized<R, N>`: const-generic operators with precomputed ψ/ω and negacyclic twiddles;
- forward: Cooley–Tukey radix-2 DIT; inverse: Gentleman–Sande radix-2 DIF;
- negacyclic twist (`forward_negacyclic` / `inverse_negacyclic`) mapping `R_q` products onto cyclic NTTs;
- `pointwise_mul` / `multiply_negacyclic`;
- `is_ntt_friendly::<R>(n)` (`q ≡ 1 (mod 2n)`, `n` a power of two);
- primitive roots and primality from `ring::number_theory` (L0 — no layering violation).

## NttDomain (M1)

`NttDomain<R, N>` is the typed NTT-domain representation: `PolyRing::to_ntt` / `from_ntt` convert explicitly, and domain-wise `add`/`sub`/`mul` run without any transform. This is what lets `Â` live transformed for its entire lifetime (ML-DSA) and what LaBRADOR-style batched openings build on.

```rust
let op = NttOperatorOptimized::<ZqD, 256>::new();
let a_ntt = a.to_ntt(&op);
let prod = Rq::from_ntt(a_ntt.mul(&b_ntt), &op);  // convolution, no transforms
```

## Parameter compatibility

A ring admits a dimension-`n` NTT iff `n` is a power of two and `q ≡ 1 (mod 2n)`:

| Parameter set | q | 2-adicity of q−1 | n | OK? |
| --- | --- | --- | --- | --- |
| ML-KEM (3329) | 3329 | 7 | 256 | ✅ (spec uses the layered NTT — see note) |
| ML-DSA (8380417) | 8380417 | 13 | 256 | ✅ |
| Falcon (12289) | 12289 | 12 | 512/1024 | ✅ (spec uses FFT; see note) |
| LaBRADOR (2^32) | 2^32 | — (composite) | 64 | reduction is a shift; NTT not applicable |

> **ML-KEM note.** FIPS 203 uses an *incomplete* NTT: `Z_3329[X]/(X^256+1)` splits into 128 quadratic factors, and NTT-domain elements are 128 two-coefficient polynomials. The generic negacyclic NTT remains mathematically valid; the spec-compatible layered instance is scheduled with ML-KEM.
>
> **Falcon note.** FIPS 206's reference uses floating-point FFT sharing the sampler's transforms; the integer NTT here serves verification and cross-checks.

## Correctness notes for ML-DSA

`ExpandA` samples `Â` **directly in the NTT domain**, so scheme correctness only requires NTT/INTT to be mutual inverses and domain ops to be consistent — any evaluation order works *mathematically*. For byte-exact KATs, however, the convention matters: ML-DSA uses the dedicated `mldsa::ntt` transform with the standard's exact ζ = 1753 and bit-reversed evaluation order `ζ^(2·brv8(i)+1)`, while this generic engine keeps its own root/ordering for the non-KAT layers.
