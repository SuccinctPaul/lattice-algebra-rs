# Ecosystem

Where this project stands relative to related work — what we build on, what we are complements to, and what we deliberately do not do.

## One-line positioning

> **arkworks is to elliptic-curve SNARKs what this project is to lattice cryptography**: not the fastest single-scheme implementation, but the composable, correct algebra substrate from which a *family* of schemes derives.

## Reference points

| Project | Positioning | Relationship |
| --- | --- | --- |

| [Plonky3](https://github.com/Plonky3/Plonky3) | field/NTT abstractions for FRI-style SNARKs (`TwoAdicField`, challenger) | **technical model**: `TwoAdicRing` ≈ `TwoAdicField`; `Transcript` ≈ `Challenger` |
| [lattice-algebra (Lazarus)](https://github.com/lattice-complete/Lazarus) | lattice algebra toolkit (R_q, modules, sampling, commitments) | closest prior art; this crate strengthens const-generic parameterization, NTT-domain representation freedom, and adds the SNARK component layer |

| [latticefold / condor-rs (Nethermind)](https://github.com/NethermindEth/latticefold) | LatticeFold(+)-lineage implementations | Z4 folding references; engineering lessons on ring tooling |

## Differentiators

1. **One foundation, two outputs.** Existing libraries serve either PQC (liboqs, RustCrypto) or ZK (LaBRADOR, latticefold — each with their own ring code). None share a norm/decomposition/NTT stack across both; shared audit points are a first-class design goal here.
2. **Representation freedom.** Explicit coefficient/NTT-domain switching (and eventually double-ring embedding) — the prerequisite for scheme-level performance and the SNARK double-ring trick.
3. **XOF-driven determinism.** Interfaces take seeds and labels, not RNGs — FIPS-aligned and KAT-friendly.
4. **Docs as design.** This site (Mermaid architecture, trait map, module map) evolves with the code; capability traits are documented at decision time, not archaeologically.

## Non-goals

- No pursuit of absolute fastest-on-every-platform (SIMD extremes yield to correctness and genericity; the performance budget focuses on NTT and modular-multiplication hot paths).
- No hash-based (SLH-DSA) or code-based (Classic McEliece) NIST candidates.
- No heavy dependencies in the base layers (GPU, big frameworks); `sha3`/`zeroize`/`rand`/`rayon`-grade dependencies are the ceiling.
