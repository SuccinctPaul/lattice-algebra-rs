# Z3 · Ring-Sumcheck & Gadget-IPA

**Status: implemented** (`src/sumcheck`) — the GreyHound-style components of the lattice zkSNARK roadmap: a multilinear sumcheck over any commutative ring and inner-product arguments on Ajtai-committed vectors with a gadget-based approximate opening. Cross-checked against Z2's batched opening on the same toy R1CS instance with size/time benchmarks.

## Ring-sumcheck (`sumcheck`)

Proves `Σ_{x ∈ {0,1}^G} T(x) = S` for an explicit truth table `T ∈ R^{2^G}`. The protocol works over **any commutative ring** — no inverses needed: per-round challenges come from a caller-supplied closure (deterministically derived from a shared transcript), and each round message is the pair of partial sums of the folded table.

```rust
let mut ch = zq_challenger(b"sumcheck-common");
let proof = prove::<Rq, 10>(&table, &mut ch);           // 1024-entry table, 10 rounds

let mut chv = zq_challenger(b"sumcheck-common");
let (challenges, final_eval) =
    verify::<Rq, 10>(&proof, sum, &mut chv).expect("verifies");
```

- Round consistency: `h_i(0) + h_i(1)` must equal the incoming claim;
- claim folding: `S_{i+1} = h_i(0) + r_i·(h_i(1) − h_i(0))`;
- soundness: G rounds of Schwartz–Zippel (2048 random bits per round on the Z2 ring); the verifier now **closes the loop** by evaluating the public residual table at the derived challenge point and matching `final_eval`.
- the companion gadget-IPA uses the same non-unit challenge fix as Z2 (`C = X − a`, `a` odd — the monomial `X` is always a unit in this ring, which made the inner-product check vacuous; a forged-claim regression test is in place).

Compared to Z2's single γ-combination of gate residuals, the sumcheck gives **round-by-round folding**: a cheating prover is committed to each intermediate folded claim, so soundness holds per round rather than amortized over one big challenge.

## Gadget-IPA (`sumcheck::ipa`)

Inner-product argument on Ajtai-committed vectors: given `c = A_com·α` and public `u`, prove `⟨α, u⟩ = v`.

- FS challenges `X` (forced non-unit) and `γ` derived from `(key, c, u, d)`;
- response `α' = α + X·mask` with mask commitment `d = A_com·mask`;
- checks: the overdetermined binding link `A_com·α' == c + X·d` and the inner-product claim `⟨α', u⟩ == v + X·t*` with `t* = ⟨mask, u⟩`;
- `X` non-unit blocks the adaptive-`t*` division attack.
- `ipa_gadget_open` + `approx_slack_bound(drop)`: the response can be opened **approximately** through a gadget split (`α' = 2^drop·hi + lo`, `|lo| ≤ 2^{drop−1}`) with the provable per-coefficient slack `D·2^{drop−1}` — the mechanism the full LaBRADOR recursion uses to keep opened values short.

## Multi-assertion batching + vanishing range claims (`sumcheck::batch`, `sumcheck::range`)

The Π_batch shape (LatticeFold's batched sumcheck): `K` claims over the same
hypercube merge into **one** round structure —

1. the challenger derives a batch weight `γ` after the statement is absorbed;
2. claims fold as `T* = Σᵢ γⁱ·wᵢ·Tᵢ` (weight `wᵢ` = all-ones or `eq(βᵢ, ·)`),
   claimed sum `v* = Σᵢ γⁱ·vᵢ`;
3. one sumcheck runs on `T*`; the single final evaluation ties the batch back
   to public data (transparent mode recomputes `combined_table`; a committed
   deployment swaps the tables for PCS openings — unchanged round structure).

Batch soundness adds a Schwartz–Zippel factor over `γ` (`≤ K/|R|`) on top of
the per-round ring bound. The vanishing-polynomial checks plug in as extra
claims: the digit-range claim applies `g_b(X) = ∏_{i=0..b}(X−i)(X+i)` (zero
set exactly `[−b, b]`) position-wise — "a sumcheck over the ℓ variables
proves every digit is in range" — and the Booleanity claim applies `X² − X`.
Over a prime ring both are **exact** for canonical representatives (a factor
`w₀² ≡ i² (mod q)` forces `w₀ ≡ ±i`; the alternative root `q − i` falls
outside the centered range once `2b < q`), and unsound over `2^k` rings —
the range/bit checks assert primality, the 2-adic line keeps its norm gates.

The NTT-diagonal strong-sampling set for the round challenges over prime
rings lands with `foundation::sampling::diagonal_set_poly` (nonzero
constants — distinct draws differ by a unit).

## Z2 × Z3 cross-check

Same toy R1CS instance (1024 squaring gates, same witness) through both proof paths:

| Path | Statement form | Proof size | Prove | Verify |
| --- | --- | --- | --- | --- |
| Z2 (batched opening) | binding link + γ-combined masked constraint | 3072 B | ~1.7 s (debug) | ~0.62 s (debug) |
| Z3 (ring-sumcheck) | residual table sumcheck over 2^10 gates | 5376 B | ~104 ms (debug) | ~1.3 ms (debug) |

(Z3 numbers from `cargo test z2_z3_crosscheck -- --nocapture`, debug build; the sumcheck's verifier work is O(G) folds over the publicly recomputable residual table, versus Z2's O(gates) row evaluation — the trade GreyHound makes.)

Both paths assert acceptance on the identical instance/witness pair — the cross-check gate required by the roadmap.

- `z2_z3_crosscheck_and_benchmarks`: both paths accept the same instance; sizes asserted (3072 B / 5376 B); timings printed.
- `batch`: honest K-claim batch with one round structure + final-eval tie-back; eq(β)-weighted claims; forged tables caught at round 1 and (self-consistent forgery) at the tie-back; γ binds the absorbed statement;
- `range`: exact bit/range checks over the prime ring (in-range and boundary values, near-modulus representatives); range-claim table sums to zero iff all digits in range; non-prime rings refused;
- `batched_sumcheck_merges_data_claims_and_range_claim` (contract test): data + eq(β) + range claims in one proof, single out-of-range digit rejected.

## What Z3 does *not* claim

- The sumcheck operates on explicitly revealed residual tables — folding the *commitment* itself into the sumcheck (so the table never becomes public) is the full GreyHound design and lands with Z4's folding layer.
- ZK still deferred (blinding/masking at Z4).
- Concrete security parameter calibration (lattice-estimator) remains an open hardening item shared with Z1/Z2.
